## 模型一：采矿编制平衡（`mining_balance.py`）

核心公式：

```
单兵产出   = 载重 / (采集时间 + 往返时间 + 交接开销)
采集时间   = 载重 / (2 × WORK)
往返时间   = 2D / 移速            D：到基地单程距离
移速       = min(1, 2 × MOVE / 体重)
spawn 吞吐 = 单兵产出 × (1500 / (3 × 部件数))    单位寿命 1500，孵化 3 tick/部件
净产出     = spawn 吞吐 − 维持成本（造价 / 1500）
```

**结论**：距离越远，最优身体越小。超过 40 格后堆身体收益趋零，只能靠数量密度。
对应实现：`config.js` 中远程兵种限价（远程采集者 450、远程接驳工 500），本地兵种不设限。

## 模型二：Spawn 门槛（`spawn_threshold.py`）

```
能量约束（资源供给）  ：可维持人数 = k × 房间供给 × 1500 / 造价     k = 换代能量占比（取 0.5）
时间约束（Spawn 生产）：可维持人数 = 1500 / (3 × 部件数)
单 spawn 制造吞吐     ：造价 / (3 × 部件数)                        E/tick
新建 Spawn 门槛       ：在役上限 × 造价 / (k × 1500)                E/tick
```

**结论**：

| 身体 | 单 spawn 吞吐 | 新建 Spawn 门槛 |
|---|---|---|
| 小型 400E（6 部件） | 22.2 E/tick | 44.4 E/tick ≈ 5 个矿源 |
| 中型 550E（8 部件） | 22.9 E/tick | 45.8 E/tick ≈ 5 个矿源 |
| 大型 800E（9 部件） | 29.6 E/tick | 59.3 E/tick ≈ 6 个矿源 |
| 满配 5000E（50 部件） | 33.3 E/tick | 66.7 E/tick ≈ 7 个矿源 |

即：**单 spawn 最多只能消化约 22~33 E/tick 的能量**。双矿源房间只有 20 E/tick，远未到瓶颈；
真正需要第二个 Spawn 的时机是"供给 > 60 E/tick 且 RCL7"，在那之前扩军只会亏在换代成本上。

## 运行

```powershell
python analysis/mining_balance.py
python analysis/spawn_threshold.py
```

> 注意：模型是**离线估算**，不含矿源再生上限（10 E/tick）与互相抢位的挤压，绝对值偏高，但曲线形状与最优点位置可用。
