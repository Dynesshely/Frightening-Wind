# 全面升级计划

> 基线：RCL4（W7N2，容量 900）· GCL 1（约 40 万 / 100 万）· 11 模块 4300 行 · 回归 33 项
> 原则：**先补短板、再扩规模**；每一阶段都有可量化验收指标，不靠感觉推进。

---

## 0. 持续观测（已建立）

`watchdog.py` 每 90 秒采样一次，7 条异常规则实时告警，日志落 `watchdog.log`：

| 规则 | 判定 | 说明 |
|---|---|---|
| `runtime_error` | `Memory.fw.errors` 新增 | 静默停摆的唯一可靠信号（上一次 spawn 被拆就是这个没盯住） |
| `mine_starved` | 全部矿源 ≥ 90% 且人口 ≥ 6 | 采集链断了 |
| `rcl_stall` | RCL 进度 300 tick 无变化 | 升级端卡死 |
| `pop_crash` | 人口跌超 30% | 单位被大量击杀 |
| `logistics_break` | 容器全空但矿源在减少 | 搬运端断裂 |
| `spawn_saturated` | spawn 利用率 > 85% | 生产能力成为瓶颈 |
| `controller_risk` | 降级倒计时 < 3000 tick | 控制器即将丢失 |

**下一步**：告警 → 自动干预（如连续 3 次 `mine_starved` 自动重置矿工角色绑定）。
